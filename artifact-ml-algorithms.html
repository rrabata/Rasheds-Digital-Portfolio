01 / A visual taxonomy

Start with the goal and data you have. Domains overlap: the same method may be used on several kinds of data.

01 · Tabular dataPredict labels, numbers, patterns or segments

Decision Trees → Random Forests / Gradient Boosting
K-means → PCA

02 · Computer visionIdentify and interpret image features

CNNs → classification
K-means / PCA → image features

03 · NLPUnderstand, classify or generate language

BERT → text understanding
GPT → text generation

04 · Generative AISynthesize new examples or content

GPT → text
GAN / Diffusion / VAE → synthetic data or imagery

Classification nuance: Supervised methods learn from labeled examples; unsupervised methods discover structure without target labels. Modern generative and transformer models often rely on self-supervised objectives, adversarial training, or generative learning. These cannot accurately be forced into only two labels; the cards identify their learning setup explicitly.

03 / What makes these approaches different?

Tree models vs. clustering

Decision Trees, Random Forests, and Gradient Boosting are commonly trained with labeled outcomes. Random Forests combine randomized trees in parallel; boosting improves learners in sequence. K-means does not predict a provided label—it discovers similar groups. PCA primarily compresses features and is not a clustering method.

Discriminative vs. generative

Discriminative applications learn to classify or predict values from existing inputs (such as defect detection). Generative methods learn to create plausible new content or samples. A CNN is typically used to recognize features, while diffusion and GAN approaches synthesize imagery.

BERT vs. GPT

BERT uses bidirectional contextual representations and is typically adapted for understanding tasks. GPT-style autoregressive transformers generate text one token at a time. Both rely on transformer attention, but they differ in architecture, objectives, and typical applications.

Model selection in operations

  1. Clarify whether the business needs prediction, segmentation, understanding, or generation.
  2. Check for labeled data, volume, quality, and privacy constraints.
  3. Choose a suitable baseline and evaluate it against meaningful business metrics.
  4. Review interpretability, bias, compute needs, and human oversight before deployment.

04 / Portfolio artifact information

Introduction & objective

This AIML-501 artifact builds a compact reference for selecting and communicating machine learning approaches. The objective is to distinguish learning styles, connect core algorithm families to Tabular Data, Computer Vision, NLP, and Generative AI, and communicate accurate operational applications.

Process & tools

I organized algorithms by task and learning objective, wrote short working descriptions, translated the techniques into business use cases, and designed an accessible, responsive HTML visualization with a downloadable SVG summary. Research references are listed below.

Deliverables

Interactive 12-algorithm visual framework; domain and relationship map; downloadable vector overview; comparison and selection guidance; citations and reflection draft for the separate assignment submission.

Professional value

The artifact demonstrates the ability to convert technical concepts into decision-oriented communication—relevant to operations strategy, analytical scoping, and discussions with cross-functional teams.

Responsible use

Use cases are illustrative proposals, not claims that models were trained, evaluated, or deployed. Any workplace adoption would require validated data, governance, fairness/privacy review, and performance testing.
